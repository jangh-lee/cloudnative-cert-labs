Kyverno 정책 실습 – KCA 시험 대비. 본 자료는 Linux Foundation·CNCF와 무관한 독립 교육자료입니다.

개요

항목값
배포 변수LAB_REPO=jangh-lee/cloudnative-cert-labs · LAB_VER=v2026.11.27
목표team 라벨 없는 같은 Pod가 정책 없음 · Policy(blue) · ClusterPolicy에서 생성 · blue만 거부 · 둘 다 거부로 바뀌는 것, 정책 READY를 출력으로 확인
범위v1.19 레거시 Policy·ClusterPolicy, 단계 0~7 + 과제, 클러스터 kca10, Namespace kca10-blue·kca10-green
버전kind v0.33.0 · node v1.35.8 · Kyverno v1.19.2(chart 3.9.2) 고정
필요 도구Docker(4GiB 이상), kind, kubectl v1.35.x(실습용 ~/.kca-lab/bin/kubectl, 1.34~1.36), helm 3.14+ · macOS 또는 Linux
시간준비 약 2분, 실습 약 12분
네트워크가이드는 오프라인 열람, setup은 node 이미지·chart 다운로드 필요
격리전용 kubeconfig ~/.kca-lab/, 기존 클러스터·~/.kube/config·현재 context 변경 없음
검증2026-11-25 아래 명령·출력 그대로 실행 확인, 도구 확인 출력은 2026-11-26 실습용 kubectl v1.35.8, setup 출력은 2026-11-25 실행(당시 kubectl v1.37.2)

OS=$(uname -s | tr A-Z a-z); ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/'); U=https://dl.k8s.io/release/v1.35.8/bin/$OS/$ARCH/kubectl
mkdir -p ~/.kca-lab/bin && (cd ~/.kca-lab/bin && T="$(mktemp kubectl.XXXXXX)" && { curl -fsSLo "$T" "$U" && echo "$(curl -fsSL "$U.sha256")  $T" | shasum -a 256 -c && chmod +x "$T" && mv "$T" kubectl || { rm -f "$T"; false; }; })

1 Policy 생성 · Ready 확인 적용 후Ready 대기

슬라이드 S11

Policy를 만들면 Kyverno 컨트롤러가 status.conditions에 Ready=True를 기록하고, wait는 그때까지 기다린다.

적용 전적용 후
생성 직후 조회 · READY 빈칸(이 실행)

policy.kyverno.io/require-team condition met

적용 후 출력

require-team   true        false        True    0s    Ready
YAML 보기 · 03-pol-require-team.yaml
apiVersion: kyverno.io/v1
kind: Policy
metadata:
  name: require-team
  namespace: kca10-blue
  labels:
    lecture.kca/lab: kca10

  background: false
  rules:
    - name: team-label
      match:
        any:
          - resources:
              kinds:
                - Pod
      validate:

        message: "team 라벨 필요"
        pattern:
          metadata:
